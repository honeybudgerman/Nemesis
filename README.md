# NEMESIS: Rise of Two Kings

Персональная RPG-стратегия: реальные задания → опыт героя и ресурсы королевства, параллельно развивается соперник Каэль.

**Статус:** Sprint 5. Готово: рабочая основа (авторизация, герой, Тронный зал, задания, XP/уровни, облачные сохранения, экспорт), соперник Каэль (независимая симуляция, хроника, сравнение, догон пропущенных дней) и наставник Орион (AI Gateway, чат, задания от Ориона, проверка ответов, лимиты AI) и королевство (карта из 12 территорий, экономика, постройки, армия, автобои, захват земель) и двор (придворные, отношения, романтические линии, интриги, политические события, личные квесты, должности).

## Стек

Next.js 15 (App Router) · TypeScript strict · Tailwind CSS 4 · TanStack Query · Zustand · Supabase (Auth + PostgreSQL + RLS) · Vitest · PWA.

## Как устроена безопасность прогресса

- Клиент **никогда** не пишет в базу. Браузер использует Supabase только для входа и чтения своих данных (RLS).
- Все изменения идут через Route Handlers (`src/app/api/*`), которые проверяют сессию и вызывают транзакционные SQL-функции
  (`start_game`, `sync_quests`, `complete_quest`, `skip_quest`, `create_manual_quest`, `delete_game`,
  `ensure_rival`, `apply_rival_days`, `reserve_ai_request`, `apply_ai_daily_quests`, `save_quest_evaluation` и др.).
  Эти функции может вызывать только `service_role`, ключ которого живёт только на сервере.
- `complete_quest` блокирует профиль (`FOR UPDATE`), проверяет ключ идемпотентности и уникальность завершения:
  повтор запроса или двойное нажатие не начисляют XP дважды. Своё задание ограничено 3 штуками и 60 XP в день.
- Все изменения ресурсов пишутся в `resource_ledger`, события — в `game_events`.
- Формулы XP (`src/engine/progression`) продублированы в SQL для атомарного пересчёта уровня; тест сверяет обе реализации.

## Соперник Каэль

- Симулятор `src/engine/simulation/rival.ts` чистый и детерминированный: результат дня зависит только от состояния Каэля,
  даты, его сида и версии правил. Активность игрока на Каэля не влияет, подстройки под игрока нет.
- Каэль получает XP по тем же правилам, что и герой (время × сложность × оценка), устаёт, отдыхает, ошибается и иногда теряет золото
  на рискованных сделках. В среднем около 35–40 XP в день.
- Симулируются только завершённые дни (по часовому поясу игрока). Пропущенные дни догоняются пачками по 31 дню:
  каждая пачка — одна транзакция `apply_rival_days` с блокировкой строки соперника, проверкой ожидаемого `last_simulated_day`
  (защита от гонок и повторов) и контрольной точкой в `simulation_checkpoints`.
- Загрузка состояния продвигает Каэля максимум на одну пачку; остальное клиент догоняет через `POST /api/rival/sync`.
- API: `GET /api/rival/profile`, `GET /api/rival/actions?limit=&before=`, `POST /api/rival/sync`.

## Наставник Орион

- Единый серверный AI Gateway (`src/server/ai/gateway.ts`, клиент `src/engine/ai/openrouter.ts`) ходит в OpenRouter.
  Модель задаётся `OPENROUTER_MODEL` (по умолчанию `openai/gpt-4.1-mini`), ключ `OPENROUTER_API_KEY` живёт только на сервере.
- Ответы с данными запрашиваются по JSON Schema и проверяются Zod на сервере. При невалидном ответе — до 3 попыток, потом запасной вариант.
- AI не меняет XP и ресурсы: задания Ориона получают XP от движка (время × сложность), оценка ответа (S–F) превращается
  в XP по тем же правилам, что и у обычных заданий. План Ориона можно получить раз в день и только пока ни одно дневное задание не закрыто.
- Лимиты (ТЗ §9.4): запросов в день и бюджет в месяц, меняются в настройках. Каждый вызов пишется в `ai_usage_logs`
  (токены и стоимость от OpenRouter). Бронирование запроса идёт под блокировкой, поэтому параллельные запросы не обходят лимит.
- Без ключа, при исчерпанном лимите или недоступности AI игра работает: остаются шаблонные задания, чат отвечает
  заготовленными советами, а задание с проверкой можно закрыть самостоятельно с оценкой B.
- API: `POST /api/ai/mentor/chat`, `POST /api/ai/mentor/evaluate`, `POST /api/ai/quests/generate`,
  `GET /api/ai/mentor/view`, `GET|PUT /api/ai/mentor/settings`.

## Королевство

- Карта из 12 территорий (сетка 4×3, соседи по сторонам): столица игрока, две земли Каэля, пять нейтральных и четыре фракционных.
  У каждой территории рельеф (бонус обороны), ресурс, гарнизон и укрепления (`src/data/realm/map.ts`).
- Экономика по фиксированным правилам (`src/engine/realm/economy.ts`): постройки × уровень × бонус рельефа, плюс доход земель,
  минус содержание армии. Провизия не уходит в минус: голод снижает мораль. Очки командования восстанавливаются по одному в день.
- Дни мира пересчитываются так же, как хроника Каэля: детерминированно, пачками по 31 день, с оптимистичной проверкой.
  В эти же дни Каэль иногда сам захватывает соседние нейтральные и фракционные земли (земли игрока в MVP он не трогает).
- Постройки: замок, ферма, рынок, казармы, академия, дворец. Одновременно идёт одна стройка, уровень растёт по окончании таймера.
  Остальные постройки не выше уровня замка + 1.
- Армия: пехота, лучники, кавалерия, маги, королевская гвардия. Найм требует казарм (и академии/замка для сильных войск), размер армии ограничен.
- Бой (`src/engine/realm/battle.ts`): сила армии × мораль × командир × тактика × случайность 0.9–1.1 против гарнизона × укрепления × рельеф.
  Seed зависит от ключа запроса, поэтому повтор того же запроса даёт тот же результат и применяется один раз. Перед атакой экран показывает шанс победы.
- Бои дают ресурсы и земли, но не опыт. Все изменения идут через SQL-функции с блокировками, ключами идемпотентности и журналом ресурсов.
- API: `GET /api/kingdom`, `GET /api/kingdom/territories`, `POST /api/kingdom/build`, `POST /api/kingdom/recruit`, `POST /api/kingdom/attack`.

## Двор

- 8 придворных (`src/data/court/npcs.ts`): 5 главных с личными квестами из трёх шагов (Лиара, Сельвина, Торвальд, Мейрин, Брам)
  и 3 второстепенных, которые присоединяются по условиям (земли, дворец, сюжет). Все персонажи взрослые.
- Характеристики 0–100: лояльность, симпатия, доверие, амбиции, ревность, влияние. Статусы: незнакомы → знакомство → дружба →
  близкие отношения; романтика и постоянная спутница только через сюжетное событие и с согласия персонажа; возможен разрыв.
- Одно действие с каждым персонажем в день: беседа, совет, подарок (не покупает симпатию сверх доверия), прогулка (с дружбы).
  Время с одной спутницей вызывает ревность у другой.
- События (`src/data/court/events.ts`): не больше одного нового в день и двух ожидающих. Последствия: отношения, связи между NPC,
  ресурсы, мораль армии и даже мирное присоединение территорий.
- Должности: командующий (ведёт армию в бой вместо правителя), казначей, канцлер, посол (ежедневный доход). Нелояльный (< 30) бонуса не даёт.
- Числа считает движок (`src/engine/court/court.ts`), AI пишет только реплики придворных (с заготовками на случай недоступности).
  База применяет изменения атомарно, с ключами идемпотентности и проверкой версий персонажей.
- API: `GET /api/court`, `GET /api/court/npcs/:id`, `POST /api/court/interact`, `POST /api/court/choose`, `POST /api/court/assign`.

## Подключение (один раз)

1. **Supabase.** В проекте откройте *Project Settings → API* и скопируйте `Project URL`, `anon public` и `service_role`.
2. **Переменные окружения.** Скопируйте `.env.example` в `.env.local` и заполните три значения Supabase.
   `SUPABASE_SERVICE_ROLE_KEY` — секрет: не коммитьте и не добавляйте префикс `NEXT_PUBLIC_`.
3. **Миграции.** Любой из способов:
   - Supabase CLI: `npx supabase login`, `npx supabase link --project-ref <ref>`, `npm run db:push`;
   - или вставьте содержимое `supabase/migrations/*.sql` (по порядку) в *SQL Editor* и выполните.
4. **Auth.** В *Authentication → URL Configuration* укажите `Site URL` (адрес приложения) и добавьте
   `https://<адрес>/auth/callback` в *Redirect URLs*. Для одного пользователя можно отключить подтверждение email
   (*Authentication → Providers → Email → Confirm email*).
5. **Запуск:** `npm install`, `npm run dev`, откройте http://localhost:3000.

### Деплой на Vercel

Импортируйте репозиторий в Vercel, добавьте те же три переменные в *Settings → Environment Variables* и задеплойте.
Для Ориона добавьте `OPENROUTER_API_KEY` (секрет, ключ из openrouter.ai/keys) и при желании `OPENROUTER_MODEL`.
Адрес деплоя добавьте в настройки Auth Supabase (шаг 4).

## Проверки

```bash
npm run typecheck   # TypeScript
npm run lint        # ESLint
npm run test:unit   # движок: XP, уровни, оценки, планировщик заданий, часовые пояса
npm run build
```

Интеграционные тесты (`tests/integration`) прогоняют миграции на реальной PostgreSQL с заглушкой Supabase Auth и проверяют
идемпотентность, гонки, лимиты, истечение заданий и RLS:

```bash
TEST_DATABASE_URL=postgres://postgres@localhost:5432/postgres npm run test:integration
```

```

src/components/     UI, пиксельные спрайты
supabase/migrations схема БД, RLS, транзакционные функции
tests/              unit и integration
```
